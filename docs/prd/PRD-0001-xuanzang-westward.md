# PRD-0001：西行·玄奘（2D 横版平台跳跃）

## Vision

把玄奘从长安出发、到那烂陀寺、再回到长安译经圆寂的十九年，压缩成**七关横版平台跳跃**。

玩家扮演的不是"打怪升级的武僧"，而是一个**靠一步一脚印走过去的人**：路要自己跳过去，风沙要靠自己扛过去，强盗要用锡杖护住自己，外道的诘难要用义理破过去。游戏的核心情绪是"**不退**"——每一关都在问同一句话：你还要不要往西走？

成功长什么样（可验收）：

1. 一个没玩过的人，能在 10 分钟内走完第一关，并自然学会**移动、跳跃、锡杖、文斗**四件事。
2. 七关各自有**一种独有的苦难机制**（沙暴、严寒、绝食、水难、辩难…），机制能被玩家看懂，也能被玩家利用。
3. 攻击有明确的**打击感四件套**：定格、震动、火花、音效，命中瞬间可被玩家"感觉到"。
4. 文斗关卡与战斗关卡都能用**不杀**的方式通关，且成败是二元的（过 / 不过）。

## 目标用户

- 主要用户：柠檬叔本人（西安，单机、中文界面、Windows 11 + Godot 4.7.2）。
- 次要用户：喜欢国风与历史题材的 2D 平台跳跃玩家。
- 使用场景：键盘（WASD/方向键 + J/K）与手柄（Xbox 布局）单机游玩，不需要联网。

## 需求列表

### REQ-0001-001 基础移动手感（平台跳跃的本分）

- 动机：平台跳跃的成败一半在"跳起来舒不舒服"。
- 范围：左右移动（带加速度/摩擦力）、可变高度跳跃、土狼时间、跳跃缓冲、进阶技巧（贴墙下滑可选）。
- 非目标：不做冲刺、不做二段跳、不做抓钩（玄奘不飞）。
- 验收口径：水平最高速度 220 px/s；跳跃峰值高度 3.2 格（每格 16 px 的整数倍换算）；土狼时间 ≥ 0.10 s；跳跃缓冲 ≥ 0.12 s。断言由 `tests/test_movement.gd` 覆盖，全部为 pass/fail。

### REQ-0001-002 锡杖与打击感

- 动机：用户明确要求"攻击要有良好的打击感、特效"。
- 范围：三段连击的锡杖横挥；命中时触发定格（hitstop）、屏幕震动、火花粒子、音效；受击方闪白与击退。
- 非目标：不做复杂连招树、不做武器养成。
- 验收口径：hitstop 0.06–0.09 s；震屏幅度 3–6 px、时长 0.15–0.25 s；命中火花粒子上限 24 个；敌人受击闪白 0.08 s；击退速度 180–260 px/s；无敌帧 0.5 s。以上均为可在 headless 测试中断言的常量。

### REQ-0001-003 心念与定力（资源系统）

- 动机：把"不杀"做成可玩的机制，而不是嘴上说说。
- 范围：`心念`（攻击/化解消耗，命中或静坐回复）、`定力`（受伤/被诘难时下降，归零即本关失败重来）。
- 非目标：不做数值养成、不做装备、不做等级。
- 验收口径：心念上限 100，锡杖单次消耗 8，命中回复 12；定力上限 3（三颗心），归零后 0.5 s 内触发关卡重开且回到最近一次checkpoint。

### REQ-0001-004 苦难机制（每关一种）

- 动机：玄奘的故事是"苦难史"，苦难必须变成玩法。
- 范围：七关各一种，机制表见下方"关卡结构"。
- 非目标：不做生存建造、不做背包负重。
- 验收口径：每种苦难机制至少有一条断言：进入对应关卡区域后，目标参数发生变化（例如 L2 沙暴风速 ±60 px/s、L4 体温值每 1.5 s 下降 1 点），离开区域后恢复。

### REQ-0001-005 文斗（辩经）系统

- 动机：用户明确要求"文斗啊，这些个的东西"。
- 范围：回合制论点对决。玩家每回合从 3–4 张"论点卡"中选择：**立论**（建立己方观点）、**破斥**（直接攻击对方论点）、**举证**（引用经论加固己方）、**静观**（回复定力）。对方的诘难按脚本回合推进，有明确"正确回应"。
- 非目标：不做自由文本输入、不接大模型（离线、脚本化、可测试）。
- 验收口径：文斗关卡有 3–6 回合；每回合正确回应使对方"论力"下降；连续两次错误回应使己方定力 -1；文斗全程不触发任何敌方伤害即判定"全胜"。断言由 `tests/test_debate.gd` 覆盖。

### REQ-0001-006 多层次视差背景

- 动机：用户点名要"差分背景图"（多层视差）。
- 范围：每关 4 层：天穹 / 远景 / 中景 / 近景。用 Godot `Parallax2D` 实现，各层 `scroll_scale` 不同，横向无缝。
- 非目标：不做昼夜循环、不做动态天气系统（L2 沙暴为关卡脚本驱动，不算通用系统）。
- 验收口径：四层均以镜像平铺方式实现横向无缝（`Parallax2D.repeat_size` 生效）；层间 `scroll_scale` 分别为 0.05 / 0.25 / 0.5 / 0.8；摄像机移动 1000 px 时四层位移分别为 50 / 250 / 500 / 800 px（headless 断言）。

### REQ-0001-007 七关结构（关卡即叙事）

- 动机：把十九年压成七关，每关一个"过不去的坎"。
- 范围：见下表，每关包含：进入理由（叙事卡）、苦难机制、敌人、出口（史实节点）。
- 非目标：v1 只交付 L1 的完整可玩竖切，其余六关只交付关卡设计、美术清单与音频设计（文档级），代码层留出接口。
- 验收口径：七关的设计表在本文档中完整；L1 可通过 headless E2E 走完全程（起点 → 3 个 checkpoint → 终点）。

### REQ-0001-008 美术资产全部由 OFOX 生成

- 动机：用户指定"精灵图、背景图、主角、敌人都交给 OFOX 的 GPT Image 2.5，用透明背景"。
- 范围：主角全套动作、敌人、Boss、视差背景层、特效素材、道具图标；统一风格串（见 ART-BIBLE）。
- 非目标：不使用其它生图供应商；不做人工重绘。
- 验收口径：每张原始图都留存 `request.json` + `inspection.json`（格式/尺寸/alpha 统计）；主角与敌人素材必须"真实 alpha"（透明像素占比 > 15%，且主体 alpha 均值 > 200）；不透明背景层必须为 1024×1024 且无文字水印。[已由 ECN-0001 变更] 追加两条：④ 同一角色的所有姿态必须来自"定版图 + 参考图条件生成"（`/v1/images/edits`，带 `background=transparent` 与显式 `size`），不得逐帧独立文生图；⑤ 每批产出必须留档与定版参考图的一致性度量（`tools/consistency_check.py`，含轮廓 IoU 与色板差异），离群帧重生成而非凑用。

### REQ-0001-009 音频设计（先文案，后实现）

- 动机：用户要求"每一关的音效设计、BGM 设计，先文案设计好"。
- 范围：七关的 BGM 基调（乐器、速度、层次、情绪曲线）与关卡内音效清单（动作、命中、环境、叙事）。
- 非目标：本轮不制作用于交付的音频文件；实现方式（合成 / 采样 / 采购）留待确认。
- 验收口径：`docs/audio/AUDIO-DESIGN.md` 中每关至少 1 条 BGM 描述（含乐器与 BPM）+ 不少于 8 条音效条目，且每条音效都标注触发时机。

### REQ-0001-010 存档与关卡切换

- 动机：七关需要进度留存。
- 范围：`user://save.json` 记录已通关卡、拾取物、最近 checkpoint；主菜单可选关；通关一关后播放叙事卡再进入下一关。
- 非目标：不做云存档、不做多存档位。
- 验收口径：`save.json` 写入后重启游戏仍可读取；关卡切换不丢拾取物；断言由 `tests/test_save.gd` 覆盖。

### REQ-0001-011 可自动化验证

- 动机：塔山循环要求"证据优先"，游戏项目也必须能自动跑。
- 范围：Godot `--headless` 下可运行的测试入口，覆盖移动、战斗、文斗、视差、存档；以及一条 L1 端到端流程。
- 非目标：不做画面像素级比对（截图比对留待后续版本）。
- 验收口径：`godot --headless --script tests/test_runner.gd` 退出码 0 且输出 `ALL TESTS PASSED`；导入项目时 stdout 无 `ERROR`/`SCRIPT ERROR` 行。

|---|---|---|---|---|---|---|---|

| L7 | 归途 | 归国路 → 长安 | 失经、衰老、时间 | 驮经箱护送（受击会掉页）、译经点灯（限时） | 盗风、水患、疲惫 | 圆寂：心灯长明（收束演出） | 圆满与告别 |

### 为什么西行（开场叙事，30 秒）

长安，译场灯火昏黄。众师所持经论残缺、义理彼此抵触，谁也说不清"众生皆可成佛"到底该怎么落地。
玄奘发愿：**"远绍如来，近光遗法"**——去天竺求《瑜伽师地论》，把话说清楚。
于是没有批文，没有车马，只有一双麻鞋、一根锡杖、一只经笥。

## 非目标（本 PRD 明确不做）

1. 不做 3D、不做联网、不做手机端。
2. 不做战斗数值养成、装备、掉落、商店。
3. 不做自由文本对话，不接在线大模型；文斗是脚本化、可测试的。
4. v1 不交付 L2–L7 的可玩实现（只交付设计、美术清单、音频设计）。
5. 不追求"像素级复古"；本作是**手绘国风 + 高清素材**，不做像素点阵。

## 未决问题（留给用户确认，不阻塞 v1）

1. 音频实现路线：合成（自制）/ 采样库 / 采购，三选一（先不动手）。
2. 是否需要中文语音（梵呗吟诵）——涉及版权与录音。
3. 手柄优先还是键盘优先（当前两者都保留映射）。
